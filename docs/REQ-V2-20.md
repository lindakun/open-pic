# MediaLib V2：商业级前沿时尚图片平台 · 20 项优化需求（修订版）

> **文档状态**：v2.2（两轮三方交叉审核完成，**待您拍板**）
> **目标**：把当前局域网媒体库（`MediaLib/1.0`，FastAPI + SQLite + 原生前端）升级为**具备商业图库产品力与前沿时尚视觉语言**的视觉资产平台。

初稿中以下措辞不可验证，已全部替换为可执行断言：

## 一、产品定位与设计原则

### 1.1 目标形态

参照 Unsplash / Pexels（发现与检索）、Behance / 500px（编辑化叙事）、Cosmos / Are.na（前沿时尚调性）、Frame.io（资产审阅工作流）的交集：

**一个「看起来像时尚杂志、用起来像专业资产库、交付起来像商业图库」的图片站。**

### 1.2 五条设计原则（裁决后续所有取舍）

| 原则 | 含义 | 当前反例 |
| :--- | :--- | :--- |
| **P1 视觉优先** | 图片即界面，UI 退居背景；排版承担叙事 | 顶栏 9 个等权重按钮，后台管理观感 |
| **P2 零抖动** | 任何异步内容都不改变已渲染元素的位置 | 无 BlurHash 占位，图片解码前为纯色块 |
| **P3 即时反馈** | 交互 < 100ms 有响应，重活走队列且进度可见 | 上传时同步生成缩略图，大图上传期间请求被占住 |
| **P4 可发现** | 任何筛选与资产都能被 URL 表达、分享、被搜索引擎理解 | 筛选状态仅存内存；分享页只有 hash id |
| **P5 可度量** | 每个商业目标都有埋点与指标闭环 | 仅 `views`/`downloads` 两个计数器 |

### 1.3 「纯图规范」（审核补充的关键约束）

商业时尚图站与后台管理系统的分野，在于**界面为图片让路**：

- 默认态**无侧栏、无底栏**，顶栏在滚动 200px 后自动隐藏，向上滚动或鼠标移至顶部 40px 内再出现。
- 卡片默认**无边框、无阴影**，仅在 hover 时浮起 2px 并显信息层（标题 / 尺寸 / 作者）。
- 信息密度靠**排版层级与留白**建立，不靠分割线与背景块。
- 数字（尺寸、体积、色值）统一用等宽字体，建立「专业工具」质感。

### 模块 A：视觉语言与浏览体验（5 项 · 24d）

#### A-01 品牌化设计系统与「纯图优先」版式 `[P0]` `4d`

- **现状**：`app.css:1` 仅 12 个 CSS 变量，正文 13.5px 系统字体栈；深浅主题靠 `html[data-theme]` 切换；顶栏 9 个按钮等权重。
- **需求**：
  - 三层 Token：`primitive`（色阶 50–950、间距 4px 栅格、层级）→ `semantic`（surface/text/accent/border）→ `component`。组件层禁止硬编码颜色。
  - 字体分层：Display（英文可变字体 WOFF2 自托管，字重 200–800）、Text（中文优先 `PingFang SC`/`Noto Sans SC` 系统栈，不加载中文字体包）、Mono（数字/尺寸标注）。字号 `clamp()` 流体，1.25 模数。
  - 落地 §1.3 纯图规范：滚动隐藏顶栏、无边框卡片、hover 信息层、去后台感。**顶栏一级动作收敛至 ≤5 个**（上传 / 抓链接 / 搜索 / 视图切换 / 更多菜单），其余（多选、任务、主题、语言）收入「更多」菜单或侧栏。
  - 增加**混排网格（Editorial Grid）**视图：非等宽瀑布流，而是按 `aspect_ratio` 与人工权重编排的 12 栅格混排版式（大图跨 6 列、小图跨 3 列），用于首页与合辑页的杂志感呈现，避免全站只有一种流水线观感。
  - 沉浸模式（快捷键 `F`）：隐藏全部 chrome，图片占满视口。
  - 深浅两主题均通过 WCAG AA。
- **验收**：
  1. 组件样式中零命中 `#hex`、`rgb(`、`hsl(` 与内联 `style="color"`（Token 文件白名单除外），提供检查脚本。
  2. 两主题下正文对比度 ≥ 4.5:1、大字号 ≥ 3:1、非文本控件边界 ≥ 3:1，脚本输出实测值。
  3. 首屏标题在 375/768/1440/2560 四档视口下字号连续变化，无断点阶跃。
  4. 滚动 200px 后顶栏隐藏，回到顶部 40px 内 120ms 内复现；`F` 键切换沉浸模式 240ms 完成。

#### A-02 编辑化首页与精选策展 `[P0]` `5d`

- **现状**：`index.html` 为「顶栏 + 侧栏 + 瀑布流」直入列表，无首屏叙事。路由仅 `/` 与 `/s/{id}`。
- **需求**：
  - 路由分离：`/` 为编辑化首页，`/browse` 为资产浏览（现有列表逻辑整体迁移），`/` 的「查看全部」进入 `/browse`。**需新增 `/browse` 后端路由**（当前不存在）。
  - 首页结构：Hero 精选（1 主图 + 强排版标题 + 作者 + CTA）→ 编辑精选带 → 主题合辑带（横向滚动，键盘 ←/→ 可用）→ 最近上新 24 项 → 「进入全部资产」。
  - 精选位通过 `PATCH /api/featured` 人工排布（有序数组），落 `featured` 表。
  - 空库与首访有引导态（上传 / 抓链接 / 导入示例）。
- **验收**：
  1. `/browse?q=城市&sort=views` 深链直达且筛选生效；`/` 不含资产瀑布流。
  2. `PATCH /api/featured` 返回 200 后，下一次 `/` 请求即呈现新排布（无缓存歧义，服务端不缓存首页数据）。
  3. 首页本地千兆网冷缓存 LCP < 2.0s（Lighthouse 移动端模拟）。
  4. 三档视口下合辑带可横向滚动，`document.body.scrollWidth === document.body.clientWidth`。

#### A-03 动效系统与共享元素转场 `[P0]` `3d`

- **现状**：仅有 150ms 级悬停过渡；无 View Transitions / FLIP；`prefers-reduced-motion` 全仓零命中。
- **需求**：
  - 动效 Token：`--dur-fast:120ms` / `--dur-base:240ms` / `--dur-slow:400ms`，3 条标准缓动曲线。组件层禁止裸写时长。
  - 卡片 → 灯箱用 `document.startViewTransition` 做共享元素转场；不支持时降级为不透明度淡入（功能不降级）。
  - 批量删除 / 上传完成插入使用 FLIP 位移动画。
  - 全局监听 `prefers-reduced-motion: reduce`，关闭位移与缩放，仅保留 ≤120ms 不透明度变化。
  - 浮层统一使用原生 `<dialog>`（当前 0 处使用，均为手写 div），免费获得焦点陷阱与 Esc 关闭。
- **验收**：
  1. 卡片进灯箱，主图 `getBoundingClientRect()` 在 240ms 内连续插值，无闪白帧。
  2. 系统开启「减弱动态效果」后，代码路径与人工验证双重确认零位移类动画。
  3. 组件样式中零命中 `transition: all` 与硬编码 `0.xs` 时长（脚本检查）。
  4. 全部模态浮层为 `<dialog>` 元素，Esc 可关闭，打开时焦点落在首个可交互元素。

#### A-04 影院级灯箱 2.0 `[P0]` `6d`

- **现状**：`app.js:359` 以 `_lg.webp` 单图 + 原生 `<video>` 呈现；**已有**滚轮缩放、拖拽平移、1:1 查看与左右切换（v1 REQ-04 部分落地）。缺对比、连播、色板、快捷键体系（全仓无 `metaKey`/组合键处理）。
- **需求**（只补缺口，不重做已有缩放）：
  - **对比模式**：选 2–4 项并排 / 叠加对比，缩放与拖动双向同步。
  - **移动端双指缩放**：`touchmove` 双指捏合缩放 + 单指拖动，与桌面滚轮行为一致（当前仅有鼠标路径）。
  - **连播放映**：`Space` 播放暂停，间隔 3/5/8s 可选，全屏无 UI，适合客户提案。
  - **色彩取样**：展示 `palette_json` 三色板，点色值复制 HEX/RGB，并支持「按此色筛选」（对接 B-05）。
  - **快捷键表**：`←/→` 切换、`+/-` 缩放、`0` 复位、`I` 信息、`D` 下载、`C` 复制直链、`Esc` 关闭、`?` 帮助浮层。输入框 / `TEXTAREA` / `contenteditable` 聚焦时全部禁用，且不拦截 IME 组字（`isComposing`）。
  - **信息面板**：分辨率、体积、格式、码率、EXIF 摘要、来源、入库时间、标签、关联合集；一键复制 Markdown / HTML / 直链三种格式。
- **验收**：
  1. 9 个快捷键生效，且输入态与 IME 组字期间不触发。

  - **位置恢复按锚点而非像素**：记录「首个可视卡片 id + 其内偏移比例」，列数变化后仍能定位到同一资产（纯像素恢复在列数变化时会偏离原锚点）。
  - 滚动位置存 `history.state`（不进 URL），返回列表时还原。
  - 弱网（`navigator.connection.saveData`）批量降为 24。
- **验收**：
  1. 加载 2000 条后 DOM 节点数稳定 < 200。
  2. 连续滚动 100 屏，滚动期间 Long Task（>50ms）数量为 0。
  3. 返回列表后首个可视卡片是同一 `itemId`；并在窗口宽度从 1440 改到 768（列数 5→3）后重试，仍定位到同一资产。
  4. 回收/复现过程中已有卡片零位移（`getBoundingClientRect` 采样断言）。

#### D-18 性能预算与运营度量（合并原 16+19）`[P1]` `4d`

- **现状**：无任何前端埋点；`/api/analytics` 仅库内统计，无时间维度与漏斗；`views`/`downloads` 为整数计数器，无事件级数据。
- **需求**：
  - **性能侧**：接入 `web-vitals` 采集 LCP/INP/CLS/TTFB，按页面类型上报 `/api/metrics`（**默认关闭，环境变量开启**）；预算：首页 LCP ≤ 2.0s、INP ≤ 200ms、CLS ≤ 0.02、JS 首包 gzip ≤ 120KB；**不建分位数看板**（内网单用户样本无意义），改为 CLI 报告脚本 `scripts/perf_report.py` 直接输出 P50/P75/P95；本地跑 Lighthouse，超预算退出码非 0。
  - **运营侧**：`events(id, item_id, type, ts, page, referrer, device, meta)`，类型含 `impression/view/download/like/collect/search/share`；曝光用 IntersectionObserver（停留 ≥1s 才计），10s 或 20 条批量上报；看板含 7/30 日趋势、Top 资产漏斗、**零结果搜索词榜**、设备与来源分布。
  - **写锁竞争**：审核指出 `db.py:153` 全局写锁串行化，高频埋点需合并为批量事务写入。
- **验收**：
  1. 访问 20 个页面后 `metrics` 表可查到对应记录，含页面类型与设备类别。
  2. 任一资产可查 7 日曝光/点击/下载漏斗，且满足曝光 ≥ 点击 ≥ 下载。
  3. 零结果搜索词能在看板筛出。
  4. 单次页面交互产生的埋点请求 ≤ 1（批量合并），埋点失败静默降级。
  5. Lighthouse 首页 LCP > 2.0s 时检查脚本退出码非 0。

## 七、风险与前置依赖

1. **NAS 算力**：AVIF 编码与批量导出 CPU 压力大，需确认核数与是否允许夜间批处理（影响 A-05、C-13）。
2. **磁盘空间**：变换缓存 + 多格式导出会带来 1.2–1.8 倍存储增长（影响 A-05、C-13）。
3. **数据迁移**：`slug / status / license / blurhash / 色相桶 / 拼音列` 需对存量资产一次性回填，须提供幂等迁移脚本与回滚方案（影响 B-06、C-11、C-12、E-19）。
4. **v1 契约兼容**：`/t/ /f/ /p/` 路径、`/api/stats`、`POST /api/upload`、`server.py` CLI 参数不可破坏（影响 A-05、D-16）。
5. **外部 AI 依赖**：B-07 / B-08 依赖外部 API，须明确成本上限与不可用时的降级路径。
6. **FFmpeg / exiftool**：EXIF 清洗与水印依赖外部二进制，需确认 NAS 环境版本。
7. **本版不含鉴权**：C-14 选片链接靠 token 访问，安全性明确不在本版范围，后续若开放公网须单独立项。
